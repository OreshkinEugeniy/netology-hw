# Домашнее задание к занятию "`Базы данных, их типы`" - `Орешкин Евгений`


### Задание 1
СУБД
Кейс
Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для каждой предметной области.

Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?

1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков. СУБД должна гарантировать целостность и чёткую структуру данных.

1.1.* Хеширование стало занимать длительно время, какое API можно использовать для ускорения работы?

1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM? СУБД должны быть гибкими и быстрыми.

1.2.* Можно ли эту задачу закрыть одной СУБД? И если да, то какой именно СУБД и какой реализацией?

1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.

1.3.* Можно ли под эту задачу использовать уже существующую СУБД из задач выше и если да, то как лучше это реализовать?

1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать со связями.

1.4.* Можно ли к этой СУБД подключить отдел закупок или для них лучше сформировать свою СУБД в связке с СУБД логистов?

1.5.* Можно ли все перечисленные выше задачи решить, используя одну СУБД? Если да, то какую именно?

Приведите ответ в свободной форме.


# 1.1 
Для бюджетирования лучше использовать реляционную SQL-СУБД, например PostgreSQL.

Причины:

финансовые данные имеют строгую структуру;
необходимы связи между проектами, договорами, бюджетами, платежами и контрагентами;
поддерживаются ACID-транзакции;
ограничения PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK помогают сохранять целостность данных;
SQL позволяет формировать сложные аналитические отчёты;

Пользователь вводит номер телефона, сумму пополнения и выбирает способ оплаты.
Система проверяет правильность номера, допустимость суммы и существование соответствующего лицевого счёта.

### Задание 3
SQL vs NoSQL
3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL.

3.1.* Какие, на ваш взгляд, преимущества у NewSQL систем перед SQL и NoSQL.

Приведите ответ в свободной форме.


# 3.1
1)Строгая структура данных.
SQL-СУБД используют заранее определённую схему, типы столбцов и ограничения. Это уменьшает вероятность появления некорректных данных.
2)Поддержка ACID-транзакций.
Операции выполняются атомарно, согласованно, изолированно и надёжно. Это особенно важно для финансовых и учётных систем.
3)Обеспечение ссылочной целостности.
Первичные и внешние ключи позволяют контролировать связи между таблицами и предотвращать появление записей, ссылающихся на несуществующие данные.
4)Сложные запросы и объединение данных.
SQL поддерживает JOIN, группировки, подзапросы, оконные функции и агрегатные операции.
5)Стандартизированный язык и развитая экосистема.
SQL применяется в большом количестве СУБД. Для него существует множество средств администрирования, резервного копирования, аналитики и мониторинга.

При этом NoSQL-системы могут превосходить SQL-СУБД в гибкости схемы и горизонтальном масштабировании. Поэтому выбор зависит от требований конкретной системы.

### Задание 4
Кластеры
Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу выделено 1000 машин.

На основе какого критерия будете выбирать тип СУБД и какая модель распределённых вычислений здесь справится лучше всего и почему?

Приведите ответ в свободной форме.


Основным критерием выбора СУБД будет способность системы горизонтально масштабироваться и распределять данные и вычисления между 1000 машин.
акже необходимо учитывать:

объём данных;
тип вычислений;
необходимость строгой согласованности;
допустимость временной недоступности части данных;
устойчивость к отказу отдельных узлов;
возможность выполнять вычисления рядом с местом хранения данных;
поддержку автоматического шардирования;
пропускную способность сети.

Для такой задачи лучше подойдёт распределённая СУБД или распределённая файловая система, способная работать по принципу shared-nothing. В архитектуре shared-nothing каждый узел имеет собственные процессор, память и диски, а данные разделяются между узлами. Это позволяет добавлять новые машины и увеличивать общую производительность системы.
